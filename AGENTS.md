# AGENTS.md — Maknae core development guidance

Canonical, tool-agnostic direction for the **AI agents and tools** that work on Maknae. `CLAUDE.md` is a symlink to this file; Codex, opencode, and other tools read `AGENTS.md` directly, so the direction is identical for every agent. Human contributors: see [`CONTRIBUTING.md`](CONTRIBUTING.md) for onboarding and the development workflow — the principles here apply to your work too, but the human-process detail lives there. This file holds **core principles and conventions**; the load-bearing detail lives in the linked authority (the KLC contract, the ADRs, the code). It is deliberately short and grows in a **measured, self-correcting style** — see [How to change this file](#how-to-change-this-file).

## Authority & currency guard

**When sources disagree, currency wins in this order: the code → the [Knowledge Lifecycle Contract](design/knowledge-lifecycle-contract.md) → current [ADRs](design/adr/) → everything else.** Older prose is suspect until reconciled. Design docs and the README describe intent at a point in time; they are not the enforcement surface and they drift.

The live example, because it will bite you: **the access-control vocabulary is fixed by [ADR-0020](design/adr/ADR-0020-access-control-model-and-vocabulary.md) (CNSSI 4009-aligned) — use it precisely.** DAC and MAC are *policy types* (discretionary vs mandatory); RBAC and ABAC are *decision models* (role- vs attribute-keyed) — orthogonal axes, not synonyms. Maknae's in-repo default is **RBAC** (`maknae-authz-basic`); the optional external classification (DCS) library (`maknae-authz-dcs`) enriches decisions to **ABAC** — role, clearance/classification, releasability, compartments, need-to-know. **Corrected 2026-08-29 (ADR-0008 amending ADR-0020 §3): a mandatory operand MAY `Permit`, on a complete evaluation of its own predicate — clearance alone is never a grant.** The earlier "constraint-only, never `Permit`" rule assumed permit-by-default with MAC subtracting; Maknae is deny-by-default, and constraint-only made an attribute-native grant (a cleared FVEY national reading `SECRET//REL USA, FVEY`) undecidable by any operand. The reference monitor composes **deny-overrides** (`crates/maknae-security`, `compose.rs::combine`): a mandatory (MAC) `Deny` is never waivable by a discretionary (DAC/RBAC) `Permit`, so an admin role — and the kernel itself — gets no clearance bypass. `maknaed` is the sole PDP ([ADR-0005](design/adr/ADR-0005-enforcement-locus-tcb-boundary.md)); per-request evaluation IS wired (corrected 2026-08-28, #77: every request is decided through the seam — `combine`+`finalize` over `maknae-authz-basic` — and the shipped deny list is enforced on the `Read` verb's PEP; the earlier "not yet wired" statement is superseded). **Older prose that calls this a "generic DAC access policy," or treats DCS labels as the in-repo model, is superseded** — the classification/DCS *evaluation* engine is the external library ([ADR-0002](design/adr/ADR-0002-kernel-is-rust.md) §Consequences; [container-architecture](design/container-architecture.md) §6), reached only through the seam. **Corrected 2026-09-06 (#148/#154): the PDP is now the `Composition` — `maknae-authz-basic` ∧ the in-repo classification-ceiling operand, both NAMED non-removable fields (ADR-0008 decision 1) — and every request is decided over both. The ceiling operand is a MANDATORY (MAC) operand: content at or below the declared level flows, content marked above it is refused, unmarked content is UNCLASSIFIED (nothing stamps a marking yet — #229 makes higher markings expressible), and it never `Permit`s; so "the classification evaluation engine is the external library" now reads precisely: the *scalpel* (compartments, releasability, need-to-know, and labeling above UNCLASSIFIED) is external; the *ceiling* over the four-level order ships in the kernel.** If stale text sends you the wrong way, fix or flag it rather than following it.

## Core principles

1. **Secure by Design and by Default.** Deny-by-default, everywhere, always. The kernel/trust plane is the only trusted code; **the agent runtime is untrusted by design.** ([KLC](design/knowledge-lifecycle-contract.md), [ADR-0005](design/adr/ADR-0005-enforcement-locus-tcb-boundary.md).)
2. **Authorization is RBAC composed with a mandatory (MAC) ceiling operand by default, ABAC when the classification library is present, composed deny-overrides.** *(Corrected 2026-09-06, #148/#154: this said "RBAC by default"; the in-repo composition now always carries the ceiling operand beside `-basic` — a MAC-type operand deciding by one attribute over the four-level order (degenerate ABAC) — at or below the declared level flows, above it is refused, unmarked is UNCLASSIFIED — evaluated on every content request, never a grant. Vocabulary per decision 1 above: MAC is the policy TYPE, one-attribute ABAC the decision MODEL.)* Access is decided by the reference monitor (`maknaed`, the sole PDP), not by prompt-level markers or content self-labeling. Injected, retrieved, and tool-supplied content may *inform* a decision but can never *authorize* one — inform-but-not-authorize. Mandatory controls (classification, SELinux) take precedence over discretionary grants; no role or privilege — not even the kernel — bypasses clearance. (`maknae-security`, `maknae-config::authz`; [ADR-0020](design/adr/ADR-0020-access-control-model-and-vocabulary.md), [ADR-0005](design/adr/ADR-0005-enforcement-locus-tcb-boundary.md).)
3. **Static Rust TCB.** The kernel is 100% Rust with a static trusted computing base — no hot-swappable core, no runtime-patchable policy path. Extensibility surfaces are attack surface; adding one is a security decision, not a convenience. ([ADR-0002](design/adr/ADR-0002-kernel-is-rust.md).)
4. **Fail closed, everywhere.** This includes the tests: the risk-tiered coverage contract is fail-closed by design — unclassified, stale, or (for non-T3 code) absent coverage is a hard failure, not a warning. ([ADR-0016](design/adr/ADR-0016-risk-tiered-test-coverage.md), [`coverage-tiers.toml`](coverage-tiers.toml).)
5. **TDD, with mutation-proofing for AI-written code, and reproduce-first for bugs.** Tests come before implementation. Because segments are AI-implemented, the suite doubles as mutation-proofing — prove each assertion can go red. For a reported defect, the *first* deliverable is a test that fails **for the reporter's reason**, observed failing, before any fix; then revert the fix once to confirm it goes red again. Test the **real decision path** (a genuine PDP verdict with a uniquely-named sentinel), not a stubbed stand-in — a stand-in proves the plumbing and hides everything else.
6. **Blind review is rigor.** Independent, fresh-context review — human or a second AI — is how we remove author blind spots. An agent reviewing its own work carries its own assumptions; treat multi-AI blind review as a control, not overhead.
7. **Modular by contract, where a real substitution axis exists.** Where a component can have more than one legitimate implementation — the authorization engine is the worked example ([ADR-0004](design/adr/ADR-0004-modular-authorization-architecture.md)) — prefer a **stable, versioned contract with swappable implementations behind it** over a hard-wired one. The failure this avoids: a hard-wired engine (Cedar-as-the-only-PDP) forces a solution that ages out before the work is done and becomes both lock-in and attack surface; a narrow, versioned seam lets the implementation change — or a third party bring their own — without touching the core. Guidance applied where it earns its keep, not a mandate to modularize everything.

## Conventions

- **Supported platforms: Linux (amd64/arm64) AND macOS on Apple Silicon (arm64) — macOS is a PRODUCTION TARGET, not a dev convenience. There are no x86 macOS builds.** The failure that motivated recording it here: this was settled by operator ruling on 2026-08-30 and written into [`packaging/isolation-contract.md`](packaging/isolation-contract.md) and [ADR-0009](design/adr/ADR-0009-subject-side-os-dac-evaluation.md) — but **not into this file**, which is the one every agent reads. A week later an agent filed [#222](https://github.com/darkhonor/maknae/issues/222) asserting *"macOS is a dev platform, not a production target"* and supported it with two citations to documents that do not mention macOS at all (`state/linux-test-hosts.md`, ADR-0016 — zero occurrences in each). A platform fact that lives only in a packaging README will be contradicted by the next agent who never opens it. **Consequences that follow, and that the #222 error nearly discarded:** a macOS gap is a *supported-platform gap*, never a reduced-profile footnote; an FFI shim on darwin puts C in the TCB **on a shipping platform**, so [ADR-0002](design/adr/ADR-0002-kernel-is-rust.md)'s 100% Rust TCB applies there with full force and there is no dev-box exemption to appeal to. *(That the operator's Mac is also the primary dev host is a fact about one machine, not about the platform class.)*
- **File and directory I/O goes through [`maknae-io`](crates/maknae-io).** The failure that motivated it: four different permission masks and three different owner rules had accumulated across `maknae-config::loader`, `maknae-config::authz`, `maknae-audit-append::sink` and `maknae-vault::secret_io`, because each site re-implemented the checks by hand — so a new backend's only options were to duplicate security-critical code or fail open. The crate pins an anchor directory as an fd and resolves every path relative to it, so the checked inode and the used inode are the same open fd — via `O_NOFOLLOW` per component on the portable lane, and `RESOLVE_NO_SYMLINKS|RESOLVE_BENEATH` on the Linux `openat2` lane (the anchor's own parent is opened by path and follows symlinks, deliberately, so a symlinked ancestor is resolved once at open time). Callers name what they require; `None` is a named, greppable value, never a silent absence. The exact-inventory `std-fs-drift` gate rejects both new direct production filesystem calls and stale exemptions; each remaining exemption records the contract gap that keeps it outside `maknae-io`.
- **Verify with the gates.** The authoritative checks live in [`ci/gates/`](ci/gates/) (`coverage-tiers.sh`, `negative-control.sh`, `isolation-contract-lint.sh`, the P1/P2 witness checks). The `negative-control` gate exists to prove a passing gate actually fails when it should — respect it; a green run that was never observed failing proves nothing.
- **Specs and plans NEVER live in the repo.** They belong in a folder **outside** this repository, in a location of the operator's choosing, per standing operator rule. If you do not have a standing location, **ask the operator before creating any working documents** such as superpowers specs or plans. This applies to all development-process artifacts (SDD workspaces, review packages, ledgers). Only shipped design documentation (ADRs, the KLC contract, the `design/references/` assessments) is committed here. Do not write a spec or plan into any path under this repo, gitignored or not.
- **Decisions get an ADR.** A choice that constrains future work is recorded as an ADR under [`design/adr/`](design/adr/), in the measured style below.
- **A semantic correction goes in the artifact itself, never only in a comment.** The failure that motivated it: a correction to issue #154's load-bearing premise — that an authorization extension "may only ever add denials", which is wrong and would have deleted the extensibility [ADR-0004](design/adr/ADR-0004-modular-authorization-architecture.md) exists for — was posted as an issue *comment*. `gh issue view` returns the **body**, not comments, so the default retrieval path every agent uses renders the superseded text and nothing else; the next agent reads the wrong premise and builds on it. **Edit the body in place with a dated banner naming what was wrong** — the same discipline this file sets for itself in [How to change this file](#how-to-change-this-file). A comment may *additionally* carry the discussion or the evidence; it may never be the only record. This holds for every artifact whose canonical form is fetched without its discussion — issue and PR bodies, ADRs, `design/references/` assessments, and this file.
- **NOTHING IS A BREAKING CHANGE WHILE WE ARE STILL BUILDING (operator ruling, repeated, 2026-08-31).** Maknae is pre-release: no client is deployed, so a protocol or daemon-contract change has nothing to break. **Do not write break-notes. Do not file compatibility events. Do not raise the topic.** The two that existed (`design/references/*.breaking.md`) were written without direction and are deleted, not migrated. The failure this replaces: prior guidance here told agents a `maknae-proto` change was "a compatibility event — bump the version or file a break-note", and agents dutifully produced ceremony documents for a system with no users, on their own authority. `design/references/` holds external assessments; it is not a compatibility ledger. This rule is revisited when something actually ships, and that is the operator's call to make, not an agent's to anticipate.

  **The operator is the SOLE governance on protocol and wire semantics (ruling 2026-08-31). Do not raise the subject. Do not propose restoring any part of the guidance this bullet replaced — including the deleted "a semantic break behind a stable wire counts" clause. Do not ask whether it should come back.** The failure that motivated it: that clause was repeatedly interpreted badly by agents, and an agent then asked to reinstate it hours after the operator ruled it out. Correctness of the policy path is enforced where it belongs — the reference monitor, the golden matrices, the coverage and mutation gates — not by prose in this file.
- **NEVER change `PROTOCOL_VERSION` without the operator's EXPLICIT authorization (operator ruling 2026-08-28).** The failure that motivated it: #77 bumped `PROTOCOL_VERSION` 1→2 on the agent's own authority — buried as a "decision" in a spec section — to add the `Read` verb. A version bump is checked strict-equality both directions, so it is an **irreversible hard mutual break**: every deployed CLI dies against the new daemon until reinstalled (live-observed as `frame truncated` on the Rocky 10 acceptance host). The bump was also unnecessary — new verbs are **additive CBOR enum variants** that keep pre-change clients working for the unchanged verbs. Default to the additive path; treat a version bump as an operator-only decision, requested explicitly and never assumed from a spec passing review.
- **Document every dependency pin.** A version pin in `Cargo.toml` records, in a comment, the exact failure it prevents. For a FIPS-140-3 / DoD-SCRM project on `aws-lc-rs`, an undocumented pin is an unreviewed control. `deny.toml` is the supply-chain gate; keep pins explained so a reviewer can see *why*, not just *what*.

## How to change this file

Write each rule as a decision record, not a slogan: state the rule, the **failure that motivated it**, and — where it matters — a measurement. When a rule turns out wrong, **correct it in place with a date and say what was wrong** ("corrected 2026-08-21: fixed the access-control vocabulary to CNSSI 4009 — RBAC default / ABAC via the DCS library, with DAC and MAC as policy types — per ADR-0020"), rather than silently editing. That is how this file stays current instead of rotting into the next DCS. Keep prose soft-wrapped (one line per paragraph); reserve manual line breaks for lists, tables, and code.
