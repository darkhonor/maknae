# AGENTS.md — Maknae core development guidance

Canonical, tool-agnostic direction for the **AI agents and tools** that work on Maknae. `CLAUDE.md` is a symlink to this file; Codex, opencode, and other tools read `AGENTS.md` directly, so the direction is identical for every agent. Human contributors: see [`CONTRIBUTING.md`](CONTRIBUTING.md) for onboarding and the development workflow — the principles here apply to your work too, but the human-process detail lives there. This file holds **core principles and conventions**; the load-bearing detail lives in the linked authority (the KLC contract, the ADRs, the code). It is deliberately short and grows in a **measured, self-correcting style** — see [How to change this file](#how-to-change-this-file).

## Authority & currency guard

**When sources disagree, currency wins in this order: the code → the [Knowledge Lifecycle Contract](design/knowledge-lifecycle-contract.md) → current [ADRs](design/adr/) → everything else.** Older prose is suspect until reconciled. Design docs and the README describe intent at a point in time; they are not the enforcement surface and they drift.

The live example, because it will bite you: **the access-control vocabulary is fixed by [ADR-0020](design/adr/ADR-0020-access-control-model-and-vocabulary.md) (CNSSI 4009-aligned) — use it precisely.** DAC and MAC are *policy types* (discretionary vs mandatory); RBAC and ABAC are *decision models* (role- vs attribute-keyed) — orthogonal axes, not synonyms. Maknae's in-repo default is **RBAC** (`maknae-authz-basic`); the optional external classification (DCS) library (`maknae-authz-dcs`) enriches decisions to **ABAC** — role *plus* clearance/classification. The reference monitor composes **deny-overrides** (`crates/maknae-security`, `compose.rs::combine`): a mandatory (MAC) `Deny` is never waivable by a discretionary (DAC/RBAC) `Permit`, so an admin role — and the kernel itself — gets no clearance bypass. `maknaed` is the sole PDP ([ADR-0005](design/adr/ADR-0005-enforcement-locus-tcb-boundary.md)); per-request evaluation is not yet wired (`authz.rs` ships/validates the grammar ahead of it). **Older prose that calls this a "generic DAC access policy," or treats DCS labels as the in-repo model, is superseded** — the classification/DCS *evaluation* engine is the external library ([ADR-0002](design/adr/ADR-0002-kernel-is-rust.md) §Consequences; [container-architecture](design/container-architecture.md) §6), reached only through the seam. If stale text sends you the wrong way, fix or flag it rather than following it.

## Core principles

1. **Secure by Design and by Default.** Deny-by-default, everywhere, always. The kernel/trust plane is the only trusted code; **the agent runtime is untrusted by design.** ([KLC](design/knowledge-lifecycle-contract.md), [ADR-0005](design/adr/ADR-0005-enforcement-locus-tcb-boundary.md).)
2. **Authorization is RBAC by default, ABAC when the classification library is present, composed deny-overrides.** Access is decided by the reference monitor (`maknaed`, the sole PDP), not by prompt-level markers or content self-labeling. Injected, retrieved, and tool-supplied content may *inform* a decision but can never *authorize* one — inform-but-not-authorize. Mandatory controls (classification, SELinux) take precedence over discretionary grants; no role or privilege — not even the kernel — bypasses clearance. (`maknae-security`, `maknae-config::authz`; [ADR-0020](design/adr/ADR-0020-access-control-model-and-vocabulary.md), [ADR-0005](design/adr/ADR-0005-enforcement-locus-tcb-boundary.md).)
3. **Static Rust TCB.** The kernel is 100% Rust with a static trusted computing base — no hot-swappable core, no runtime-patchable policy path. Extensibility surfaces are attack surface; adding one is a security decision, not a convenience. ([ADR-0002](design/adr/ADR-0002-kernel-is-rust.md).)
4. **Fail closed, everywhere.** This includes the tests: the risk-tiered coverage contract is fail-closed by design — unclassified, stale, or (for non-T3 code) absent coverage is a hard failure, not a warning. ([ADR-0016](design/adr/ADR-0016-risk-tiered-test-coverage.md), [`coverage-tiers.toml`](coverage-tiers.toml).)
5. **TDD, with mutation-proofing for AI-written code, and reproduce-first for bugs.** Tests come before implementation. Because segments are AI-implemented, the suite doubles as mutation-proofing — prove each assertion can go red. For a reported defect, the *first* deliverable is a test that fails **for the reporter's reason**, observed failing, before any fix; then revert the fix once to confirm it goes red again. Test the **real decision path** (a genuine PDP verdict with a uniquely-named sentinel), not a stubbed stand-in — a stand-in proves the plumbing and hides everything else.
6. **Blind review is rigor.** Independent, fresh-context review — human or a second AI — is how we remove author blind spots. An agent reviewing its own work carries its own assumptions; treat multi-AI blind review as a control, not overhead.

## Conventions

- **Verify with the gates.** The authoritative checks live in [`ci/gates/`](ci/gates/) (`coverage-tiers.sh`, `negative-control.sh`, `isolation-contract-lint.sh`, the P1/P2 witness checks). The `negative-control` gate exists to prove a passing gate actually fails when it should — respect it; a green run that was never observed failing proves nothing.
- **Specs and plans NEVER live in the repo.** They belong in a folder **outside** this repository, in a location of the operator's choosing, per standing operator rule. If you do not have a standing location, **ask the operator before creating any working documents** such as superpowers specs or plans. This applies to all development-process artifacts (SDD workspaces, review packages, ledgers). Only shipped design documentation (ADRs, the KLC contract, the `design/references/` assessments) is committed here. Do not write a spec or plan into any path under this repo, gitignored or not.
- **Decisions get an ADR.** A choice that constrains future work is recorded as an ADR under [`design/adr/`](design/adr/), in the measured style below.
- **Protocol/daemon-contract discipline.** A change to the `maknaed`↔`maknae` protocol (`crates/maknae-proto`, `crates/maknae-msgs`) is a compatibility event — bump the protocol version or file a break-note, and run an old-daemon/new-client interop check before relying on it. **A semantic break behind a stable wire counts** (a field whose *meaning* shifts under an unchanged shape): on a policy protocol, that is how a deny silently becomes a permit. (Full gate is tracked as separate follow-on work; the discipline applies now.)
- **Document every dependency pin.** A version pin in `Cargo.toml` records, in a comment, the exact failure it prevents. For a FIPS-140-3 / DoD-SCRM project on `aws-lc-rs`, an undocumented pin is an unreviewed control. `deny.toml` is the supply-chain gate; keep pins explained so a reviewer can see *why*, not just *what*.

## How to change this file

Write each rule as a decision record, not a slogan: state the rule, the **failure that motivated it**, and — where it matters — a measurement. When a rule turns out wrong, **correct it in place with a date and say what was wrong** ("corrected 2026-08-21: fixed the access-control vocabulary to CNSSI 4009 — RBAC default / ABAC via the DCS library, with DAC and MAC as policy types — per ADR-0020"), rather than silently editing. That is how this file stays current instead of rotting into the next DCS. Keep prose soft-wrapped (one line per paragraph); reserve manual line breaks for lists, tables, and code.
