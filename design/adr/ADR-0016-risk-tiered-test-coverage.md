# ADR-0016: Risk-tiered test coverage — objective, fail-closed evidence that security-critical code is tested

- **Status:** Accepted (operator-ratified 2026-08-04)
- **Date:** 2026-08-04
- **Deciders:** Alex Ackerman (operator), Byeori (Claude Fable 5, pair)
- **Addresses:** issue #24 (risk-tiered coverage policy), operator-directed
- **Source spec:** `2026-08-04-coverage-tiers-design.md` (out-of-repo design spec; specs never live in this repository) (v18; converged through 17 critical-review rounds, 48 criticals remediated)
- **Provenance (never authority, per the ADR README doctrine):** the operator's prior standards in MPE-ES (tiered-testing model) and Microkosmos (runner-readiness "verify before run") informed this design; every rule below is decided here.

## Context

Maknae's catastrophic failure mode is not a crash — it is a **fail-open access decision or a silently widened label**: false assurance. A flat coverage number lets a healthy project average sit on top of an under-tested reference monitor. Coverage rigor must scale with how security-critical the code is, and the evidence must be objective and mechanically collected: our proof that this codebase is not AI slop is the testing. Where something genuinely cannot be tested, that is documented, anchored, and justified — never silently skipped (operator directive).

## Decision

**The line-drawing rule** (the authority for tier assignment — never a file's crate or directory):

> If this code silently breaks, can the engine return `Permit` for an access policy denies, derive a label less restrictive than its sources, or emit false assurance? Yes → T1.

**Tiers and bars** (enforced by `ci/gates/coverage-tiers.sh` + `ci/gates/coverage_check.py` against the machine-readable contract `coverage-tiers.toml` at the repo root):

| Tier | Bar |
|---|---|
| T1 security-critical | ≥95% **production-region** coverage per file + crate mutation gate: `cargo mutants` **zero missed** (TIMEOUT = investigate-failure, never ignored) |
| T2 standard | ≥90% production-region per file + cohort ratchet |
| T3 report-only | No floor; membership per-file with a written justification, never a blanket glob. T3 exempts a file from floors — not its crate from mutation |

**Mutation testing is risk-based and exists for external provability** (operator, 2026-08-04): MLS/DCS/security-critical crates (`mutants_crates`, initially the DCS classification engine — since relocated to a separate private library) must be provable to external third parties as fail-closed and policy-exact. Coverage says the code ran; killed mutants say the tests would notice if it lied.

*(Amended 2026-10-04, [#443](https://github.com/darkhonor/maknae/issues/443): at `b360cbe` the `maknae-io` lane reported 1 missed and 17 timeouts. The missed mutant was in `macos_full_path_error`, which the hand-written native platform filter did not name; platform-gated code is now derived from source by `ci/gates/platform-gated.py`, which fails when the filter does not name it. The 17 timeouts were mutants that stopped the read-path loops in `page.rs` (`Scan::peek`, `Scan::take`, `read_page`) and the loop in `mutation.rs` `replace_bytes` from advancing, so a hung test held the libtest binary until the 60 s mutant timeout. Measured with the final configuration on the RHEL 10 dev host: 316 caught, 0 missed, 0 timeout, 0 caught only by termination of 317 tested outcomes, in 10m51s, with no temporary directories left behind. A mutant whose test phase shows a nextest `TIMEOUT` and no failure status was caught only by termination; it counts as caught only when a reviewed entry in `ci/gates/mutation-terminated.txt` names its platform, file and function exactly and fully matches its replacement, and otherwise the gate fails, so TIMEOUT = investigate still holds. nextest does not run doctests; `maknae-io` has none. Named residual: statement-level `#[cfg]` inside an active fn, including items nested within the gated statement (in `anchor.rs`, `delegated.rs` and `syslog_io.rs`), is attributed to the enclosing fn and is not derivable by name; the hoisting convention keeps it mutant-free today.)*

**The metric, precisely.** Region coverage from `cargo llvm-cov --workspace --all-features --json` on the pinned toolchain, schema-asserted (export type/major-version/arity), bucketed per file via `file_id`, deduplicated by region tuple, merged any-nonzero, `kind == 0` only. **Production-region** = regions before the file's single column-0 `#[cfg(test)] mod` marker (which must extend to end-of-file; multiple/misplaced markers and zero-production files are hard failures) — Rust's in-file unit tests otherwise inflate the denominator 1.6–5×, letting production sit at 88% while the file reports 97%. This gate metric intentionally diverges from `cargo llvm-cov`'s per-file summary (which dedups function records); the baseline table shows all three numbers so nothing is conflated. Branch coverage is **omitted from the gate entirely**: `--branch` is nightly-only and a stable run emits a false `branches: 0%`; the mutation gate is the stronger semantic instrument, and chasing branch arms mutation proves behavior-inert produces valueless tests. Recorded as a revisit point, not a permanent stance.

**The fail-closed partition.** Every git-tracked `*.rs` file in the repository, outside the segment-aware instrument excludes (member-level `tests/`, `benches/`, `examples/`, `build.rs`), must resolve to exactly one tier. Unclassified, stale, double-classified, or (non-T3) absent-from-coverage = hard failure — new code cannot silently dodge the gate.

**The cohort ratchet.** The project floor applies to an explicitly recorded cohort (at adoption, the DCS classification engine's T1 files — since relocated; currently empty), production regions only — a raw aggregate over a growing mixed-tier set would spuriously block the first conforming T2 landing. Re-baselining is deliberate, with mandatory typed provenance (`value/date/lane/command` — real TOML keys the gate validates). Floors move up freely; a deletion-consequential recompute is exempt from ceremony; **discretionary lowering requires an amendment to this ADR**. The gate mechanically enforces provenance *shape*; distinguishing consequential from discretionary lowering is a human review-time control — stated as such.

**Documented exceptions** (documented-not-tested): a line span may leave a file's denominator only via an anchored `[[exception]]` entry with a non-empty `Why`-equivalent; the gate fails closed on zero/multi-match anchors, non-instrumentable (zero-region) anchors, and stale (all-covered) spans, and prints the removed-region count so reviewers see the carve-out size. Never a dodge for testable logic.

**Runner readiness** (decided here; Microkosmos/MPE-ES provenance): verify-then-run. Every readiness item is a presence/version check — never a stage's own work — stage-scoped to what the invocation selects, with copy-paste install commands on failure and advisory-only lines for unselected stages (the opt-in pre-push hook must not hard-fail a developer over a tool for a stage it doesn't run). CI provisions, then verifies the same way.

**Environment-dependent coverage:** signal-interpretation logic must be unit-testable against synthetic fixtures and counts toward the floor (testing your own logic on invented data is not gaming; asserting real-world facts from fake data is, and is forbidden). Real-environment integration tests are env-gated and skip cleanly. Genuinely un-instrumentable-on-CI code uses the `env_bound` discriminator (closed grammar, native-lane-enforced) — never a silent carve-out. The authoritative measurement lane is CI (ubuntu-latest); other hosts get an advisory.

**Enforcement surfaces:** the gate runs in CI (fixture suite first — 87 fixtures: 81 forced-failure modes with mode-identifying assertions plus 6 pass-path/positive cases, including four live-root modes and per-exclude-glob positive/near-miss pairs — then the live gate), as an **opt-in** pre-push hook (`git config core.hooksPath ci/hooks`; "lead a horse to water" — CI is the enforcement of record), and the change-gated mutation job (dependency-selected on PR and push to `main`, with documentation-only jobs skipped before runner allocation; corrected 2026-09-06 by the #126 amendment below — the earlier path-only PR and unconditional-main rule is superseded). The workflow-sync check makes contract↔workflow drift a gate failure.

**Resolved decisions recorded:** opt-in pre-push (operator); risk-based mutation scope (operator); runner-readiness model (operator); pinned-toolchain/branch-omission (operator); scaffold stubs = T3 with per-file justification, re-tiered at body landing (`bins/maknaed/src/main.rs` and the privileged-capability crates are named T1 candidates). Editing rule: per the ADR-0001 amendment landed with this change (cited, not declared here) — a `Proposed` ADR is editable in place; an `Accepted` ADR is append-only.

## Consequences

- The coverage step adds a second full instrumented build+test run to CI plus tool installs (~minutes); the fixture suite's live-root modes add three small instrumented builds; the mutation job pulls its own toolchain when triggered. Accepted: the gate is the SA-11 evidence. A binstall/tool-cache optimization, the isolation-contract negative-control gap, and line-level diff coverage are **named follow-ons**. *(Corrected 2026-09-04, [#219](https://github.com/darkhonor/maknae/issues/219): the isolation-contract negative-control gap is CLOSED. `isolation-contract-lint.sh` was the only gate in `ci/gates/` with no probe at all — it resolved its root from the CWD and so could not be pointed at a fixture. It now takes the same `${1:-…}` root override its siblings have and carries a probe for every branch it has, including a floored accept against the real contract. The other two follow-ons remain open.)*
- The workspace coverage build does NOT establish isolation (the same caveat ci.yml records for `cargo test --workspace`).
- **Marking the mutation job a required status check is an operator repo-settings action outside this deliverable.**
- Supersessions: `design/container-architecture.md` "mutation runs are scheduled, not per-commit" and ADR-0002's "scheduled mutation testing" control-mapping phrase (amended append-only) are superseded by the dependency-selected per-PR and main-push model (corrected 2026-09-06, #126). The relocated DCS engine's "mutation gate owed as a wired CI step" obligation was closed by this deliverable before relocation. Issue #24's "dogfooded to its own bar" phrasing is superseded: the gate tooling is verified by forced-failure fixtures (stronger evidence for a ~200-line helper than a percentage), and sits outside the Rust coverage universe — stated, not silent.
- A test-only module in its own file (`src/tests.rs`-shaped, no marker) would read as production; the tier-assignment review must catch that shape (review-time rule).

## Amendment — 2026-09-06, affected CI (#126)

The earlier unconditional-main mutation rule and path-only PR gate are superseded. They spent scarce hosted minutes on documentation-only merges while missing reverse-dependency and shared-input effects on PRs. `ci/affected.py` now compares a PR merge base to its head, and a push's before/after endpoints, with NUL-delimited paths and renames represented as deletion plus addition. It selects complete changed packages and their transitive reverse dependents across normal, development, build and target-specific dependencies; the mutation and Darwin cohorts intersect that closure. Missing history, empty diffs, shared configuration, unknown paths and uncertain dependency resolution select all. Invalid package or mutation authority fails. Documentation skips require an explicit allowlist, on both PR and main pushes. Required job names and unique main-run concurrency remain unchanged; a selector failure cannot silently skip those required controls.

Every source-changing run still measures the complete aggregate coverage report and enforces all file floors, partition rules and cohort ratchets. Partial coverage reports would weaken the contract, so selection does not narrow that stage. Mutation uses whole packages, zero missed, with fresh outcomes; cargo-mutants 27.1.0 has an executable-only cache keyed by OS, architecture, toolchain and version. No hosted macOS mutation job is added. The opt-in local hook uses the actual incoming ref endpoints, and selected mutation is an explicit `MAKNAE_PRE_PUSH_MUTANTS=1` option. Real Git history fixtures establish docs-only PR/merge behavior, reverse-dependency inclusion and conservative fallbacks; gate fixtures remain independent evidence that coverage enforcement fires.

### Amendment — 2026-11-04, #593, mutation over the PR's diff

A mutation run that belongs to a PR mutates only the PR's diff. It is passed every `[t1].mutants_crates` crate, and the gate decides which of them run; `affected.py`'s package selection still picks the packages for whole-package runs. This supersedes "Mutation uses whole packages" in the selection paragraph above for PR runs; the zero-missed rule and the fresh outcomes are unchanged. Pre-selecting packages for an in-diff run was a whole-package cost optimisation that the gate does not need, and it was a bypass: the selector classes `README.md` as documentation, so a push that changed only a `README.md` a production `include_str!` embeds never reached the gate. The measurement behind it, across 800 `ci.yml` runs: a mutation job took 3–14 minutes in early August and 35–36 minutes by 2026-09-07, almost all of it on mutants in code the branch never touched. The maintainer ruled on 2026-11-02 that mutation runs only on code changed in the branch.

`coverage-tiers.sh --mutants <pkg>... --in-diff <rev>` diffs `HEAD` against the merge base with `<rev>` and decides each package from the mutants cargo-mutants lists for it, with and without `--in-diff`. There are three outcomes. SKIP: no mutant sits on a changed line, so nothing runs. RUN: `cargo mutants --in-diff` runs over the diff and goes through the existing oracle, TIMEOUT and terminated-mutant checks. FAIL: a mutant sits on a changed line but the in-diff list omits it, which is a mapping failure, the silent-skip class that made a green run mutate nothing. An empty diff never reaches the mutating run. `mutation-oracle.sh judge --in-diff --expect <n>` FAILs a run whose `total_mutants` is not the `<n>` mutants the in-diff listing named, and accepts an all-unviable run only when the unmutated baseline passed.

A change that alters what is compiled without a mapped `.rs` line runs whole packages, and the compiler decides which changes do. The gate classifies every path `git diff --name-only` reports over the range, with no pathspec. For each `mutants_crates` crate the scope rules below do not already run whole, it runs `cargo check --package <c> --lib --bins` with the crate's `mutants_features` on the snapshot, into a target directory in the gate's scratch, and reads the dep-info (`.d`) files cargo writes for that crate's library and binary targets. Dep-info comes before every exemption: each changed path present at `HEAD`, documentation and lockfile included, is looked up in it, and a path whose file (compared by device and inode) appears there is a production input of the crate. Every dep-info entry must resolve to an existing file, or the run FAILs; an entry is never dropped. The crate then runs whole in four cases, and otherwise the diff maps the path. The include scan's file set comes from the compiler as well: it is the union of the production dep-info inputs of every workspace package, read from one `cargo check --workspace --lib --bins` on the snapshot and from `cargo check --package <c> --lib --bins` with the declared features for each `mutants_crates` crate that declares `mutants_features`. Every input is scanned whatever its suffix or directory, files `exclude_globs` removes and crates outside `mutants_crates` included, and only inline test modules are skipped. A file in no production dep-info is not production input, so integration tests, benches, examples and out-of-line `#[cfg(test)]` modules are not scanned. Directory names decide nothing: a library at `[lib] path = "examples/lib.rs"` or `"src/lib.rust"` is scanned like any other, and both shapes had hidden an include site from the earlier scan of tracked `.rs` files outside `tests/`, `benches/` and `examples/`. The first case is a path that is the literal target of an `include_str!` or `include_bytes!` in a file the crate's production dep-info names, even when the path is also a module: `whole: <c>: changed <path> is embedded by include_str!/include_bytes!`. Tokenizing means comments, string contents and inline `#[cfg(test)]` and `#[cfg(all(test, …))]` modules do not count, accepts the `core::`, `::core::` and `std::` paths, and resolves the literal relative to the file that contains it. The second is any scanned input that names the identifier `include_str` or `include_bytes` in any form other than a direct call with one string literal (optionally through `std::`, `core::`, `::std::` or `::core::`), such as a `use … as` alias, a `pub use` re-export, a `macro_rules!` body, a non-literal argument (`concat!`, `env!`) or another path, which runs every mutation crate whole whenever the range changes anything, since the alias can be used from any crate: `whole: <c>: include_str/include_bytes used indirectly in <file>`. Any alias, re-export or wrapper written in the workspace has to name the identifier, so this lexical check is complete for in-workspace code. The third is a crate that walks a source file whose name does not end in `.rs` (`[lib] path = "src/lib.rust"`), which the `*.rs` diff cannot map: `whole: <c>: walked source <file> is not a .rs file the in-diff mapping reads`. The fourth is a path that is not walked: `whole: <c>: changed <path> is compiled into <c> but not walked by cargo-mutants`. Together they cover include data whatever its suffix, `include_str!("policy.rs")` beside `pub mod policy;` included, a `README.md` a production target embeds, a file embedded from another crate's directory, which runs the embedding crate whole, and a file an `exclude_globs` entry in `.cargo/mutants.toml` removes. A crate whose dep-info names a changed path FAILs when `--mutants` omits it. A failed check, no dep-info for a crate's production targets, an empty or non-JSON file list, or a scanned input that names `include_str` or `include_bytes` and cannot be read or tokenized FAILs; none is read as "no inputs". Only a changed path no crate's production dep-info names can be exempt: integration tests, benches, examples, out-of-line `#[cfg(test)]` modules and data no production target reads run nothing (the test-only residual below), documentation on `ci/affected.py`'s allowlist (the same list, imported, not copied) changes nothing, and a deleted path is not at `HEAD`, so the `mod` edit that removed it is what the diff maps. The scope rules below are independent of dep-info. These files run all `mutants_crates` whole: the workspace `Cargo.toml` and any `Cargo.toml` outside every crate, `coverage-tiers.toml`, `.cargo/config` and `.cargo/config.toml`, `.cargo/mutants.toml`, `.config/nextest.toml`, `rust-toolchain` and `rust-toolchain.toml`, the workflow, `ci/affected.py` and the mutation gate's scripts and `mutation-terminated.txt`. A crate's own `Cargo.toml` runs that crate whole. Three kinds of change are exempt, because the maintainer ruled dependency and lockfile changes a named residual: `Cargo.lock`, a `Cargo.toml` edit that changes only dependency tables (`[dependencies]`, `[dev-dependencies]`, `[build-dependencies]`, the same three under `[target.*]`, and `[workspace.dependencies]`), and a `Cargo.toml` edit that leaves the parsed data unchanged (comments, formatting). Manifests are compared parsed; an added or removed manifest, or one that does not parse at either revision, is not exempt. A `mutants_crates` crate with a build script (`[package].build`, or a `build.rs` at the crate root) runs whole on any change, checked before every exemption (documentation, the test-only residual, dependency and lockfile edits), because a build script's inputs are not in the library's dep-info: a `build.rs` that reads `README.md` into `cargo:rustc-env` changes production behaviour through a documentation edit. In-diff mode refuses four shapes before any listing, and names the whole-package run (no `--in-diff`, or `MUTATION_IN_CI=true`) as the way through. The first is any tracked path in `HEAD`'s tree that contains a newline or another control character, named in its escaped (JSON) form: dep-info is newline-delimited, and `include_str!("policy\nname.txt")` split its entry, so the dependency vanished and the gate printed PASS. The second is any symlink in `HEAD`'s tree whose target is absolute or resolves outside the repository. The third is a symlink inside a `mutants_crates` crate's directory, resolving into one, or aliasing an ancestor of one, because cargo-mutants names the module by its alias path while the diff names the target. Containment is compared by filesystem identity (device and inode), not by spelling, so `alias -> CRATES/A/src` on a case-insensitive filesystem is refused. The fourth is a build script whose path is absolute or leaves the repository, because the diff cannot see its edits. In-diff mode also refuses, before any listing, a `.cargo/mutants.toml` at `HEAD` that does not parse or sets any top-level key other than `exclude_globs` and `exclude_re`: `all_features`, `features`, `no_default_features`, `additional_cargo_args` and the rest change what cargo-mutants builds, the dep-info checks build with exactly the features the gate passes, and an `all_features = true` committed before the base let a feature-gated include site go unscanned and the gate print PASS; Maknae's file sets only the two exclusion keys. The repository's only symlink, `CLAUDE.md -> AGENTS.md`, is relative and inside the tree, and passes; the repository has no build scripts. The cost is stated: a production `cargo check` of every `mutants_crates` crate the scope rules leave in-diff, measured at 79 s cold for Maknae's 18 and 2 s warm, plus the workspace check for the include scan (41 s with an empty target directory, seconds after the per-crate checks); an edit to an excluded file (for example `crates/maknae-vault/src/client.rs`) runs that crate whole; a change to a scope file runs every `mutants_crates` entry whole. Mutation stays opt-in, so the cost is paid only when someone asks for a run. The whole-package run also remains for `MUTATION_IN_CI` and `--mutants-all`, and is expected to be rare.

In-diff mode lists and mutates a snapshot of `HEAD`, never the working tree. After resolving the base and `HEAD`, the gate writes `HEAD`'s tree into the run's scratch directory from the object store (`git ls-tree` and `git cat-file --batch`: raw blobs and modes, so no attribute, filter, `export-ignore` or `export-subst` applies; a submodule entry FAILs). Both listings and every run, whole-package scope runs included, execute there, so cargo resolves the workspace from `HEAD`'s `Cargo.lock`, `.cargo/` and toolchain file. The `--output` directory stays `<root>/target/mutants-<crate>`. cargo-mutants names files relative to the snapshot root, which is the git toplevel, so they match the diff's `b/` paths (pinned by `conformance.py`). Crate directories come from `cargo metadata` on the snapshot too. A working tree that differs from `HEAD` therefore cannot change what is listed or mutated: an `--assume-unchanged` or `--skip-worktree` entry hid a removed `mod` declaration from `git status`, and discovery then omitted the changed module, so every package SKIPped. The dirty-tree check stays as an early message. `coverage-tiers.toml` must equal `HEAD`'s, and so must the gate's own scripts, `ci/affected.py` and `mutation-terminated.txt` when the gate runs from the root's `ci/gates`, because the gate reads those from where it runs. `git archive` was rejected for the snapshot: it honours `export-ignore` and `export-subst`, including from the uncommitted `$GIT_DIR/info/attributes`. cargo-mutants already builds every mutant in its own copy of the tree, so the snapshot adds the copy and no build.

Diff bases are the push's own endpoints, never a guessed `origin/main`. The pre-push hook (`MAKNAE_PRE_PUSH_MUTANTS=1`) diffs an existing ref against its remote oid and a new ref against `<remote>/HEAD`, and `MAKNAE_PRE_PUSH_MUTANTS_BASE=<rev>` overrides either. For every pushed ref with a base, documentation-only or not, the hook passes every `[t1].mutants_crates` crate, read from `coverage-tiers.toml`, and the gate decides which run. CI's `run-mutants` label does the same, diffs against `HEAD^1`, the first parent of the PR merge commit, and runs even when `affected.py` selects no mutation package; `MUTATION_IN_CI=true` keeps the whole-package run over `affected.py`'s selection. The gate's `scope crate <c> not selected by --mutants` and `changed crate <c> not selected by --mutants` FAILs stay as backstops for a caller that passes fewer. The gate SKIPs an untouched crate; when the diff changes some `.rs` file, it lists each untouched crate once with and once without `--in-diff` to prove the SKIP, which costs seconds per crate and builds nothing. A bad rev, no merge base, a dirty or untracked tree, or a root that is not the git toplevel FAILs. The root is made absolute and physical (`cd -P`) before any path is built, so CI's `--root .` names the same output directory and oracle inputs from inside the snapshot. History that can be substituted is refused before any selection: grafts, a shallow repository, and any ref under `refs/replace/`. The gate refuses it in in-diff mode, `ci/affected.py` refuses it whenever it computes a merge base (`--event pull_request`, which CI's PR selection uses), and the pre-push hook refuses it with `affected.py --check-history` before its first selection when `MAKNAE_PRE_PUSH_MUTANTS=1`. The refusal has to come first because the merge base decides what the diff contains: grafting both endpoints onto an ancestor that holds `HEAD`'s code made the range "documentation only". Grafts and shallow history change the parents a merge base is computed from, and a replace ref can substitute a base commit carrying `HEAD`'s tree. `GIT_NO_REPLACE_OBJECTS=1` stays exported at every git caller in `ci/`, and `GIT_GRAFT_FILE` is cleared there with the repository and pathspec variables, so a refusal is never the only control. The push-range selection without mutation is a diff of two trees, which none of these change, so it still accepts a shallow clone; CI fetches with `fetch-depth: 0`, so a refusal there means the checkout was tampered with.

The diff is limited to `*.rs` files; a non-Rust production input (for example `include_str!` data) runs the crates that compile it whole while every other crate SKIPs. The mapping rule is per mutant. A file is keyed by its `+++ b/` path. Every removed run marks the new-side line before it, and a pure deletion also marks the line after (unless the deletion ends a hunk at end of file), which is how cargo-mutants itself maps a deletion; every added line marks itself. Every whole-package mutant whose line span overlaps a marked line must appear by name in the in-diff list, or the run FAILs. The diff is generated with `GIT_DIFF_OPTS` and git's pathspec and repository variables cleared, replacement objects disabled (`GIT_NO_REPLACE_OBJECTS=1` at every git caller in `ci/`), `--unified=3`, `--text`, explicit `a/` and `b/` prefixes and no external diff or textconv, so a contributor's git configuration cannot change it, and a header the parser does not recognise FAILs. Without `--text`, a `*.rs -diff` attribute made git print `Binary files … differ` with no hunks, and without clearing `GIT_LITERAL_PATHSPECS` the `*.rs` pathspec matched nothing; both read as no change, so every package SKIPped. A binary diff now FAILs, and the files the diff names must equal `git diff --name-only` over the same range. `ci/gates/tests/mutation-diff/conformance.py` lists from the same kind of snapshot with real cargo-mutants in CI's `build-and-gate` job and is the control on that rule.

Four residuals are named. A test-only change (an inline `#[cfg(test)]` module, an out-of-line test module, an integration test, a bench or an example) touches no production input, so its diff-only run SKIPs; the control is the T1 95% and T2 90% production-region floors, the cohort ratchet and TDD. A change inside a crate outside `mutants_crates` selects nothing, though a mutants crate may depend on it; the full test suite and coverage still run on it. A dependency or lockfile change (`Cargo.lock`, a dependency-table-only manifest edit, `[workspace.dependencies]`) SKIPs every package; the full test suite and coverage still run on it. A third-party macro that embeds a file which is also a module of the consuming crate is a named residual: the gate sees neither the macro's name nor its file read. Today's dependency graph has no file-embedding crates, and its proc macros are derives only. The residuals belong to the coverage contract and the full test suite rather than to mutation; mutation is one method of establishing that code is defended, and test coverage is another.
