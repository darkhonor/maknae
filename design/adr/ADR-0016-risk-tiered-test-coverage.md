# ADR-0016: Risk-tiered test coverage — objective, fail-closed evidence that security-critical code is tested

- **Status:** Accepted (operator-ratified 2026-08-04)
- **Date:** 2026-08-04
- **Deciders:** Alex Ackerman (operator), Byeori (Claude Fable 5, pair)
- **Addresses:** issue #24 (risk-tiered coverage policy), operator-directed
- **Source spec:** `2026-08-04-coverage-tiers-design.md` (out-of-repo design spec; specs never live in this repository) (v18; converged through 17 critical-review rounds, 48 criticals remediated)
- **Provenance (never authority, per the ADR README doctrine):** the operator's prior standards in MPE-ES (tiered-testing model) and Microkosmos (runner-readiness "verify before run") informed this design; every rule below is decided here.

## Context

Maknae's catastrophic failure mode is not a crash — it is a **fail-open access decision or a silently widened label**: false assurance. A flat coverage number lets a healthy project average sit on top of an under-tested reference monitor. Coverage rigor must scale with how security-critical the code is, and the evidence must be objective and mechanically collected: our proof that this codebase is not AI slop is the testing. Where something genuinely cannot be tested, that is documented, anchored, and justified — never silently skipped (operator directive).

## Decision

**The line-drawing rule** (the authority for tier assignment — never a file's crate or directory):

> If this code silently breaks, can the engine return `Permit` for an access policy denies, derive a label less restrictive than its sources, or emit false assurance? Yes → T1.

**Tiers and bars** (enforced by `ci/gates/coverage-tiers.sh` + `ci/gates/coverage_check.py` against the machine-readable contract `coverage-tiers.toml` at the repo root):

| Tier | Bar |
|---|---|
| T1 security-critical | ≥95% **production-region** coverage per file + crate mutation gate: `cargo mutants` **zero missed** (TIMEOUT = investigate-failure, never ignored) |
| T2 standard | ≥90% production-region per file + cohort ratchet |
| T3 report-only | No floor; membership per-file with a written justification, never a blanket glob. T3 exempts a file from floors — not its crate from mutation |

**Mutation testing is risk-based and exists for external provability** (operator, 2026-08-04): MLS/DCS/security-critical crates (`mutants_crates`, initially the DCS classification engine — since relocated to a separate private library) must be provable to external third parties as fail-closed and policy-exact. Coverage says the code ran; killed mutants say the tests would notice if it lied.

*(Amended 2026-10-04, [#443](https://github.com/darkhonor/maknae/issues/443): at `b360cbe` the `maknae-io` lane reported 1 missed and 17 timeouts. The missed mutant was in `macos_full_path_error`, which the hand-written native platform filter did not name; platform-gated code is now derived from source by `ci/gates/platform-gated.py`, which fails when the filter does not name it. A mutant whose test phase shows a nextest `TIMEOUT` and no failure status was caught only by termination; it counts as caught only when a reviewed entry in `ci/gates/mutation-terminated.txt` names its platform, file and function exactly and fully matches its replacement, and otherwise the gate fails, so TIMEOUT = investigate still holds. nextest does not run doctests; `maknae-io` has none. Named residual: statement-level `#[cfg]` inside an active fn, including items nested within the gated statement (in `anchor.rs`, `delegated.rs` and `syslog_io.rs`), is attributed to the enclosing fn and is not derivable by name; the hoisting convention keeps it mutant-free today.)*

**The metric, precisely.** Region coverage from `cargo llvm-cov --workspace --all-features --json` on the pinned toolchain, schema-asserted (export type/major-version/arity), bucketed per file via `file_id`, deduplicated by region tuple, merged any-nonzero, `kind == 0` only. **Production-region** = regions before the file's single column-0 `#[cfg(test)] mod` marker (which must extend to end-of-file; multiple/misplaced markers and zero-production files are hard failures) — Rust's in-file unit tests otherwise inflate the denominator 1.6–5×, letting production sit at 88% while the file reports 97%. This gate metric intentionally diverges from `cargo llvm-cov`'s per-file summary (which dedups function records); the baseline table shows all three numbers so nothing is conflated. Branch coverage is **omitted from the gate entirely**: `--branch` is nightly-only and a stable run emits a false `branches: 0%`; the mutation gate is the stronger semantic instrument, and chasing branch arms mutation proves behavior-inert produces valueless tests. Recorded as a revisit point, not a permanent stance.

**The fail-closed partition.** Every git-tracked `*.rs` file in the repository, outside the segment-aware instrument excludes (member-level `tests/`, `benches/`, `examples/`, `build.rs`), must resolve to exactly one tier. Unclassified, stale, double-classified, or (non-T3) absent-from-coverage = hard failure — new code cannot silently dodge the gate.

**The cohort ratchet.** The project floor applies to an explicitly recorded cohort (at adoption, the DCS classification engine's T1 files — since relocated; currently empty), production regions only — a raw aggregate over a growing mixed-tier set would spuriously block the first conforming T2 landing. Re-baselining is deliberate, with mandatory typed provenance (`value/date/lane/command` — real TOML keys the gate validates). Floors move up freely; a deletion-consequential recompute is exempt from ceremony; **discretionary lowering requires an amendment to this ADR**. The gate mechanically enforces provenance *shape*; distinguishing consequential from discretionary lowering is a human review-time control — stated as such.

**Documented exceptions** (documented-not-tested): a line span may leave a file's denominator only via an anchored `[[exception]]` entry with a non-empty `Why`-equivalent; the gate fails closed on zero/multi-match anchors, non-instrumentable (zero-region) anchors, and stale (all-covered) spans, and prints the removed-region count so reviewers see the carve-out size. Never a dodge for testable logic.

**Runner readiness** (decided here; Microkosmos/MPE-ES provenance): verify-then-run. Every readiness item is a presence/version check — never a stage's own work — stage-scoped to what the invocation selects, with copy-paste install commands on failure and advisory-only lines for unselected stages (the opt-in pre-push hook must not hard-fail a developer over a tool for a stage it doesn't run). CI provisions, then verifies the same way.

**Environment-dependent coverage:** signal-interpretation logic must be unit-testable against synthetic fixtures and counts toward the floor (testing your own logic on invented data is not gaming; asserting real-world facts from fake data is, and is forbidden). Real-environment integration tests are env-gated and skip cleanly. Genuinely un-instrumentable-on-CI code uses the `env_bound` discriminator (closed grammar, native-lane-enforced) — never a silent carve-out. The authoritative measurement lane is CI (ubuntu-latest); other hosts get an advisory.

**Enforcement surfaces:** the gate runs in CI (fixture suite first — 87 fixtures: 81 forced-failure modes with mode-identifying assertions plus 6 pass-path/positive cases, including four live-root modes and per-exclude-glob positive/near-miss pairs — then the live gate), as an **opt-in** pre-push hook (`git config core.hooksPath ci/hooks`; "lead a horse to water" — CI is the enforcement of record), and the change-gated mutation job (dependency-selected on PR and push to `main`, with documentation-only jobs skipped before runner allocation; corrected 2026-09-06 by the #126 amendment below — the earlier path-only PR and unconditional-main rule is superseded). The workflow-sync check makes contract↔workflow drift a gate failure.

**Resolved decisions recorded:** opt-in pre-push (operator); risk-based mutation scope (operator); runner-readiness model (operator); pinned-toolchain/branch-omission (operator); scaffold stubs = T3 with per-file justification, re-tiered at body landing (`bins/maknaed/src/main.rs` and the privileged-capability crates are named T1 candidates). Editing rule: per the ADR-0001 amendment landed with this change (cited, not declared here) — a `Proposed` ADR is editable in place; an `Accepted` ADR is append-only.

## Consequences

- The coverage step adds a second full instrumented build+test run to CI plus tool installs (~minutes); the fixture suite's live-root modes add three small instrumented builds; the mutation job pulls its own toolchain when triggered. Accepted: the gate is the SA-11 evidence. A binstall/tool-cache optimization, the isolation-contract negative-control gap, and line-level diff coverage are **named follow-ons**. *(Corrected 2026-09-04, [#219](https://github.com/darkhonor/maknae/issues/219): the isolation-contract negative-control gap is CLOSED. `isolation-contract-lint.sh` was the only gate in `ci/gates/` with no probe at all — it resolved its root from the CWD and so could not be pointed at a fixture. It now takes the same `${1:-…}` root override its siblings have and carries a probe for every branch it has, including a floored accept against the real contract. The other two follow-ons remain open.)*
- The workspace coverage build does NOT establish isolation (the same caveat ci.yml records for `cargo test --workspace`).
- **Marking the mutation job a required status check is an operator repo-settings action outside this deliverable.**
- Supersessions: `design/container-architecture.md` "mutation runs are scheduled, not per-commit" and ADR-0002's "scheduled mutation testing" control-mapping phrase (amended append-only) are superseded by the dependency-selected per-PR and main-push model (corrected 2026-09-06, #126). The relocated DCS engine's "mutation gate owed as a wired CI step" obligation was closed by this deliverable before relocation. Issue #24's "dogfooded to its own bar" phrasing is superseded: the gate tooling is verified by forced-failure fixtures (stronger evidence for a ~200-line helper than a percentage), and sits outside the Rust coverage universe — stated, not silent.
- A test-only module in its own file (`src/tests.rs`-shaped, no marker) would read as production; the tier-assignment review must catch that shape (review-time rule).

## Amendment — 2026-09-06, affected CI (#126)

The earlier unconditional-main mutation rule and path-only PR gate are superseded. They spent scarce hosted minutes on documentation-only merges while missing reverse-dependency and shared-input effects on PRs. `ci/affected.py` now compares a PR merge base to its head, and a push's before/after endpoints, with NUL-delimited paths and renames represented as deletion plus addition. It selects complete changed packages and their transitive reverse dependents across normal, development, build and target-specific dependencies; the mutation and Darwin cohorts intersect that closure. Missing history, empty diffs, shared configuration, unknown paths and uncertain dependency resolution select all. Invalid package or mutation authority fails. Documentation skips require an explicit allowlist, on both PR and main pushes. Required job names and unique main-run concurrency remain unchanged; a selector failure cannot silently skip those required controls.

Every source-changing run still measures the complete aggregate coverage report and enforces all file floors, partition rules and cohort ratchets. Partial coverage reports would weaken the contract, so selection does not narrow that stage. Mutation uses whole packages, zero missed, with fresh outcomes; cargo-mutants 27.1.0 has an executable-only cache keyed by OS, architecture, toolchain and version. No hosted macOS mutation job is added. The opt-in local hook uses the actual incoming ref endpoints, and selected mutation is an explicit `MAKNAE_PRE_PUSH_MUTANTS=1` option. Real Git history fixtures establish docs-only PR/merge behavior, reverse-dependency inclusion and conservative fallbacks; gate fixtures remain independent evidence that coverage enforcement fires.

### Amendment — 2026-11-04, #593, mutation over the PR's diff

A mutation run that belongs to a PR mutates only the PR's diff. It is passed every `[t1].mutants_crates` crate, and the gate decides which of them run; `affected.py`'s package selection still picks the packages for whole-package runs. This supersedes "Mutation uses whole packages" in the selection paragraph above for PR runs; the zero-missed rule and the fresh outcomes are unchanged. Pre-selecting packages for an in-diff run was a whole-package cost optimisation that the gate does not need, and it was a bypass: the selector classes `README.md` as documentation, so a push that changed only a `README.md` a production `include_str!` embeds never reached the gate. The measurement behind it, across 800 `ci.yml` runs: a mutation job took 3–14 minutes in early August and 35–36 minutes by 2026-09-07, almost all of it on mutants in code the branch never touched. The maintainer ruled on 2026-11-02 that mutation runs only on code changed in the branch.

`coverage-tiers.sh --mutants <pkg>... --in-diff <rev>` diffs `HEAD` against the merge base with `<rev>` and decides each package from the mutants cargo-mutants lists for it, with and without `--in-diff`. There are three outcomes. SKIP: no mutant sits on a changed line, so nothing runs. RUN: `cargo mutants --in-diff` runs over the diff and goes through the existing oracle, TIMEOUT and terminated-mutant checks. FAIL: a mutant sits on a changed line but the in-diff list omits it, which is a mapping failure, the silent-skip class that made a green run mutate nothing. An empty diff never reaches the mutating run. `mutation-oracle.sh judge --in-diff --expect <n>` FAILs a run whose `total_mutants` is not the `<n>` mutants the in-diff listing named, and accepts an all-unviable run only when the unmutated baseline passed.

An in-diff run mutates the mutants on the PR's changed `.rs` lines and nothing else. Scope files, crate and workspace manifests, build scripts and their helpers, `include_str!`/`include_bytes!` targets (direct, indirect or aliased), compiled files cargo-mutants does not walk, and walked sources without `.rs` get no mutation in a PR run; tests and goldens cover data-only behaviour. Whole crates run only on request: `--mutants` without `--in-diff`, `--mutants-all`, or `MUTATION_IN_CI=true`. Dep-info is read only to find the crates that own the changed `.rs` files, and only when `--mutants` omits some `mutants_crates` crate: CI and the hook pass every one, so nothing can be unselected and the gate builds nothing. On a narrower run, when the range changes a `.rs` file present at `HEAD`, the gate runs, for each `mutants_crates` crate, `cargo check --package <c> --lib --bins --tests` with the crate's `mutants_features` on the snapshot, into a target directory in the gate's scratch, with a profile that inherits `test` (`--config 'profile.mutation-discovery.inherits="test"' --profile mutation-discovery`), so `cfg(debug_assertions)` and other profile-dependent `cfg`s match the mutation run, and `--tests`, so cargo resolves features as the mutation test build does. It reads the dep-info (`.d`) of units with `profile.test` false and a library or binary kind; a kept unit without exactly one locatable `.d` FAILs, and every dep-info entry must resolve to an existing file, or the run FAILs. A crate owns a changed `.rs` file that its dep-info names (compared by device and inode) and that lies under the crate's own directory. A file another crate only embeds is owned by no one. The unsafe-confinement gate (`ci/gates/unsafe_check.py`, ADR-0027) is the control for `#[path]`: it refuses every `#[path]` attribute in the repository, so no module lies outside its crate's directory or carries a suffix the diff cannot read. A crate that owns a changed file FAILs when `--mutants` omits it. In-diff mode refuses five shapes before any listing, and names the whole-package run (no `--in-diff`, or `MUTATION_IN_CI=true`) as the way through. The first is any tracked path in `HEAD`'s tree that contains a newline or another control character, named in its escaped (JSON) form: dep-info is newline-delimited, and `include_str!("policy\nname.txt")` split its entry, so the dependency vanished and the gate printed PASS. The second is any symlink in `HEAD`'s tree whose target is absolute or resolves outside the repository. The third is a symlink inside a `mutants_crates` crate's directory, resolving into one, or aliasing an ancestor of one, because cargo-mutants names the module by its alias path while the diff names the target. Containment is compared by filesystem identity (device and inode), not by spelling, so `alias -> CRATES/A/src` on a case-insensitive filesystem is refused. The fourth is a build script whose path is absolute or leaves the repository, because the diff cannot see its edits. The fifth is a `[lib]`, `[[bin]]` or `[[test]]` `path` in a `mutants_crates` crate's manifest that does not end in `.rs`, or a tracked path under the crate's directory whose name ends in a case variant of `.rs` (`foo.RS`), because the `*.rs` diff cannot map it; the message names the file and asks for a rename to `.rs`. After a crate's whole listing, and before its in-diff listing is judged, the gate also FAILs when a listed mutant's `file` is not a byte-exact tracked path at `HEAD`: on APFS a case-variant stem (`src/Foo.rs` for `mod foo`) or a differently normalised Unicode name is walked under a spelling the diff never names, and the change would otherwise SKIP. In-diff mode refuses, right after argument parsing and before `coverage-tiers.toml`, `cargo metadata` or any manifest is read, a symlink (mode `120000` at `HEAD`) at any config input the gate reads by path: `.cargo` and anything under it, any `Cargo.toml`, `coverage-tiers.toml`, `rust-toolchain` and `rust-toolchain.toml`, because the object store holds the link text, not the file cargo reads. The same first step refuses a tracked path that case-folds to a config input, or to a directory holding one, without being byte-identical to it (`.CARGO/mutants.toml`, `Cargo.TOML`, `Coverage-Tiers.toml`), because a case-insensitive filesystem such as APFS serves it to cargo-mutants under the canonical name while an exact-name lookup sees no file; and `coverage-tiers.sh --root <r> --in-diff-preflight` runs exactly this first step, which the opted-in pre-push hook and CI's mutation job call before they read `coverage-tiers.toml`. In-diff mode also refuses, before any listing, a `.cargo/mutants.toml` at `HEAD` that does not parse or sets any top-level key other than `exclude_globs` and `exclude_re`: `all_features`, `features`, `no_default_features`, `additional_cargo_args` and the rest change what cargo-mutants builds, the dep-info checks build with exactly the features the gate passes, and an `all_features = true` committed before the base let a feature-gated include site go unscanned and the gate print PASS; Maknae's file sets only the two exclusion keys. The repository's only symlink, `CLAUDE.md -> AGENTS.md`, is relative and inside the tree, and passes; the repository has no build scripts. The cost for CI's and the hook's full selection is no build at all; a narrower `--mutants` run pays a production `cargo check` of each `mutants_crates` crate when a `.rs` file changes, measured at 79 s cold for Maknae's 18 and 2 s warm. There is no workspace include scan and no whole-crate run. The widening this replaced cost 4h 13m on PR #600, about an hour on the crypto-profile bump and about 7 hours on #621, because almost every security PR touches a scope file. Mutation stays opt-in, so the cost is paid only when someone asks for a run. The whole-package run also remains for `MUTATION_IN_CI` and `--mutants-all`, and is expected to be rare. *(Corrected 2026-11-10, [#603](https://github.com/darkhonor/maknae/issues/603): this said a change that alters what is compiled without a mapped `.rs` line runs whole packages, so scope files, crate and workspace manifests, build-script crates, direct, indirect and aliased `include_str!`/`include_bytes!` targets, non-`.rs` walked sources and compiled-but-not-walked files each ran crates whole, found by a workspace include scan and a `--list-files` walk. By the maintainer's rulings of 2026-11-05 and 2026-11-10, an in-diff run mutates the PR's changed lines and nothing else.)*

In-diff mode lists and mutates a snapshot of `HEAD`, never the working tree. After resolving the base and `HEAD`, the gate writes `HEAD`'s tree into the run's scratch directory from the object store (`git ls-tree` and `git cat-file --batch`: raw blobs and modes, so no attribute, filter, `export-ignore` or `export-subst` applies; a submodule entry FAILs). Both listings and every run execute there, so cargo resolves the workspace from `HEAD`'s `Cargo.lock`, `.cargo/` and toolchain file. The `--output` directory stays `<root>/target/mutants-<crate>`. cargo-mutants names files relative to the snapshot root, which is the git toplevel, so they match the diff's `b/` paths (pinned by `conformance.py`). Crate directories come from `cargo metadata` on the snapshot too. A working tree that differs from `HEAD` therefore cannot change what is listed or mutated: an `--assume-unchanged` or `--skip-worktree` entry hid a removed `mod` declaration from `git status`, and discovery then omitted the changed module, so every package SKIPped. The dirty-tree check stays as an early message. `coverage-tiers.toml` must equal `HEAD`'s, and so must the gate's own scripts, `ci/affected.py` and `mutation-terminated.txt` when the gate runs from the root's `ci/gates`, because the gate reads those from where it runs. `git archive` was rejected for the snapshot: it honours `export-ignore` and `export-subst`, including from the uncommitted `$GIT_DIR/info/attributes`. cargo-mutants already builds every mutant in its own copy of the tree, so the snapshot adds the copy and no build. *(Corrected 2026-11-10, [#603](https://github.com/darkhonor/maknae/issues/603): this said "whole-package scope runs included", naming a run that no longer exists. By the maintainer's rulings of 2026-11-05 and 2026-11-10, an in-diff run mutates the PR's changed lines and nothing else.)*

Diff bases are the push's own endpoints, never a guessed `origin/main`. The pre-push hook (`MAKNAE_PRE_PUSH_MUTANTS=1`) diffs an existing ref against its remote oid and a new ref against `<remote>/HEAD`, and `MAKNAE_PRE_PUSH_MUTANTS_BASE=<rev>` overrides either. For every pushed ref with a base, documentation-only or not, the hook passes every `[t1].mutants_crates` crate, read from `coverage-tiers.toml`, and the gate decides which run. CI's `run-mutants` label does the same, diffs against `HEAD^1`, the first parent of the PR merge commit, and runs even when `affected.py` selects no mutation package; `MUTATION_IN_CI=true` keeps the whole-package run over `affected.py`'s selection. The gate's `changed crate <c> not selected by --mutants` FAIL stays as the backstop for a caller that passes fewer; `--partial`, valid only with `--in-diff`, turns it into `PARTIAL: <c> owns changed lines and is not selected; its in-diff mutants are not run here` for an explicit shard across hosts, and the verdict then covers only the selected crates, which the summary states as `PASS (partial: N crates not run): coverage-tiers gate`. CI and the hook never pass it. The gate SKIPs an untouched crate; when the diff changes some `.rs` file, it lists each untouched crate once with and once without `--in-diff` to prove the SKIP, which costs seconds per crate and builds nothing. A bad rev, no merge base, a dirty or untracked tree, or a root that is not the git toplevel FAILs. The root is made absolute and physical (`cd -P`) before any path is built, so CI's `--root .` names the same output directory and oracle inputs from inside the snapshot. History that can be substituted is refused before any selection: grafts, a shallow repository, and any ref under `refs/replace/`. The gate refuses it in in-diff mode, `ci/affected.py` refuses it whenever it computes a merge base (`--event pull_request`, which CI's PR selection uses), and the pre-push hook refuses it with `affected.py --check-history` before its first selection when `MAKNAE_PRE_PUSH_MUTANTS=1`. The refusal has to come first because the merge base decides what the diff contains: grafting both endpoints onto an ancestor that holds `HEAD`'s code made the range "documentation only". Grafts and shallow history change the parents a merge base is computed from, and a replace ref can substitute a base commit carrying `HEAD`'s tree. `GIT_NO_REPLACE_OBJECTS=1` stays exported at every git caller in `ci/`, and `GIT_GRAFT_FILE` is cleared there with the repository and pathspec variables, so a refusal is never the only control. The push-range selection without mutation is a diff of two trees, which none of these change, so it still accepts a shallow clone; CI fetches with `fetch-depth: 0`, so a refusal there means the checkout was tampered with. *(Corrected 2026-11-10, [#603](https://github.com/darkhonor/maknae/issues/603): this named both the scope-crate and the changed-crate FAILs as backstops; the scope-crate FAIL went with the scope widening. By the maintainer's rulings of 2026-11-05 and 2026-11-10, an in-diff run mutates the PR's changed lines and nothing else.)*

The diff is limited to `*.rs` files; a non-Rust production input (for example `include_str!` data) gets no mutation in a PR run, and a non-`.rs` compiled source in a mutation crate is refused. The mapping rule is per mutant. A file is keyed by its `+++ b/` path. Every removed run marks the new-side line before it, and a pure deletion also marks the line after (unless the deletion ends a hunk at end of file), which is how cargo-mutants itself maps a deletion; every added line marks itself. Every whole-package mutant whose line span overlaps a marked line must appear by name in the in-diff list, or the run FAILs. The diff is generated with `GIT_DIFF_OPTS` and git's pathspec and repository variables cleared, replacement objects disabled (`GIT_NO_REPLACE_OBJECTS=1` at every git caller in `ci/`), `--unified=3`, `--text`, explicit `a/` and `b/` prefixes and no external diff or textconv, so a contributor's git configuration cannot change it, and a header the parser does not recognise FAILs. Without `--text`, a `*.rs -diff` attribute made git print `Binary files … differ` with no hunks, and without clearing `GIT_LITERAL_PATHSPECS` the `*.rs` pathspec matched nothing; both read as no change, so every package SKIPped. A binary diff now FAILs, and the files the diff names must equal `git diff --name-only` over the same range. `ci/gates/tests/mutation-diff/conformance.py` lists from the same kind of snapshot with real cargo-mutants and is the control on that rule. It runs locally, not in hosted CI, where mutation tooling runs only on opt-in. *(Corrected 2026-11-10, [#603](https://github.com/darkhonor/maknae/issues/603): this said a non-Rust production input runs the crates that compile it whole. By the maintainer's rulings of 2026-11-05 and 2026-11-10, an in-diff run mutates the PR's changed lines and nothing else.)*

Four residuals are named. A change with no changed `.rs` line gets no mutation. A test-only change (an inline `#[cfg(test)]` module, an out-of-line test module, an integration test, a bench or an example) touches no production input, so its diff-only run SKIPs; the control is the T1 95% and T2 90% production-region floors, the cohort ratchet and TDD. A change inside a crate outside `mutants_crates` selects nothing, though a mutants crate may depend on it; the full test suite and coverage still run on it. A dependency or lockfile change (`Cargo.lock`, a manifest edit) with no `.rs` change SKIPs every package; the full test suite and coverage still run on it. The residuals belong to the coverage contract and the full test suite rather than to mutation; mutation is one method of establishing that code is defended, and test coverage is another. *(Corrected 2026-11-10, [#603](https://github.com/darkhonor/maknae/issues/603): this named four residuals: a test-only change; a change inside a crate outside `mutants_crates`; a dependency or lockfile change (`Cargo.lock`, a dependency-table-only manifest edit, `[workspace.dependencies]`); and a third-party macro that embeds a file which is also a module of the consuming crate. The last concerned only widening detection, which no longer exists; a change with no changed `.rs` line is now named instead, and a manifest edit of any kind is now in the dependency residual. By the maintainer's rulings of 2026-11-05 and 2026-11-10, an in-diff run mutates the PR's changed lines and nothing else.)*
