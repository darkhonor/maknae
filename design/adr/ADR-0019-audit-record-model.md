# ADR-0019: Audit record model — AU-3-complete content now, cryptographic integrity/non-repudiation deferred to ADR-0007

- **Status:** Accepted (operator-ratified 2026-08-11)
- **Date:** 2026-08-11
- **Deciders:** Alex Ackerman (operator), Claude (pair)
- **Addresses:** the audit trail the `maknaed` trust plane emits — its record content, sinks, compliance posture, and the boundary between what an open-source project can ship and what a National Security System deployer supplies.
- **Relates to:** ADR-0005 (the mTLS negative suite requires fail-closed rejections to emit audit events); ADR-0007 (key & signature model — owns the audit hash-chain / signing this ADR defers to); ADR-0018 (the authorization decisions these records capture); ADR-0016 (tiering).
- **Source spec:** `~/claude-memory/maknae/specs/2026-08-11-maknae-stage3a-it-responds.md`.

## Context

ADR-0005's negative suite requires every fail-closed rejection to emit an audit event, and the operator's target posture is an audit trail **compliant with the public DoD/CNSS audit requirements** for an HHH National Security System with the Classified Information Overlay. A review of the authoritative public references (NIST SP 800-53r5 AU family; NIST SP 800-53B HIGH baseline; CNSSI 1253 (2022); the Classified Information Overlay) established three facts that shape this decision:

1. **The Classified Information Overlay is silent on audit-record *content*.** It adds only AU-6/AU-12/AU-14/AU-16 (insider-threat monitoring). Record *content*, *timestamps*, *protection*, and *non-repudiation* are governed by the **800-53B HIGH baseline + CNSSI 1253**, not by an overlay-pinned field list — and the overlay does **not** mandate a classification-marking field inside audit records.
2. **AU-9(3) (cryptographic integrity) and AU-10 (non-repudiation) are HIGH-baseline requirements** that mandate audit records be cryptographically integrity-protected and non-repudiably bound to the acting identity — i.e., signed. This is the ADR-0007 "key & signature model" domain.
3. **The concrete NSS event catalog and AU-3(1) additional-field list live in CNSSI No. 1015 — which is CUI.** An open-source project can neither ingest it nor embed requirements derived from it.

## Decision

**1. Audit-record content is AU-3 / AU-3(1)-complete against the *public* standards, now.** Every generated record carries the six mandatory AU-3 elements plus the AU-3(1) additional information drawn from the *public* AU-3(1) discussion:

| Field | AU-3 element |
|---|---|
| `ts` — RFC 3339 UTC (or explicit offset), sub-second (ms) | AU-3b + AU-8 |
| `event` — event type/description | AU-3a |
| `where` — host, component, socket | AU-3c |
| `source` — peer plane URI-SAN, uid/gid/pid | AU-3d |
| `subject` — resolvable identity (uid → user, plane URI-SAN) | AU-3f |
| `action` — verb | AU-3a |
| `outcome` — result + reason + resulting posture | AU-3e |
| `session_id`, `seq` — connection correlation, ordering | AU-12(1) |

Because ADR-0018 authorizes on **group membership**, logging the specific uid/user within the group *is* AU-3(1)'s "individual identities of group-account users," and `outcome.reason` *is* the "access-control rule invoked" — the public AU-3(1) intent is satisfied natively.

**2. Cryptographic integrity (AU-9(3)) and non-repudiation (AU-10) are deferred to ADR-0007 — as a tracked gap, and one whose closure is *not yet a committed obligation*.** Each record reserves an `integrity: { prev_hash, sig }` envelope; the record schema is canonicalizable so an audit-signing capability (hash-chain + signature) bolts on **without a format break**. Until it ships, the deployment is **not** AU-9(3)/AU-10-complete. Honesty on the deferral target: **ADR-0007 today mandates only a bare audit hash-chain** (partial AU-9 — it detects single-record edits, and is explicitly *not* irrefutable against a trust-plane compromise) and scopes the externalized/signed anchor that actually completes AU-9(3)/AU-10 as **accreditation-driven / optional (a "COULD")**. So the `integrity.sig` producer **does not yet exist as a committed requirement** — closing this gap for a real NSS ATO requires a committed **amendment to ADR-0007** upgrading that anchor from optional to a tracked MUST-for-NSS. This ADR flags that dependency rather than implying ADR-0007 already owns it as a MUST.

**3. Two sinks now; SIEM offload as a config seam (AU-9(2)).** Records are written to a dedicated **`_maknae`-owned append-only JSONL file** **and** mirrored to **journald/syslog** (the macOS unified log as the equivalent). A `maknae.yaml` `audit:` section is the declared seam for an **external SIEM collector**, satisfying AU-9(2) (store on a physically separate system) **when configured** (the default two sinks are same-host). **AU-5 posture applies during operation, not only at startup:** if the primary sink cannot be opened at boot **or** a write to it fails at runtime, the daemon **fails closed**. (The journald/syslog mirror is best-effort and does not by itself relieve the fail-closed requirement on the primary sink.)

**Ordering — so "fail closed" is actually realizable.** A post-hoc audit-write failure cannot un-apply a side effect, so the fail-closed guarantee depends on record *ordering* relative to execution:
- **Stage 3a's verbs are read-only (`whoami`/`ping`).** The record is written and **durably flushed to the primary sink before the response is released** (audit-then-respond); a write failure withholds the response — fail closed, with no side effect to undo.
- **Mutating verbs (issue #67, Stage 3b+) cannot be made fail-closed by a post-hoc write.** They require **two-phase** audit — a pre-execution *decision/intent* record durably written **before** the side effect (the operation is refused if it cannot be), plus a post-execution *completion* record capturing the outcome. Corrected 2026-09-07 (#158): this pattern now serves `fs.write`, `fs.delete`, and `fs.mkdir`; typed mutation metadata correlates intent, progress, and completion by `session_id` + `intent_seq`. The mutation amendment below defines the observed/reported distinction.

**4. The OSS-vs-CUI boundary is explicit.** Maknae ships requirements derived only from **public** standards. The **CNSSI-1015-specific** NSS event list and AU-3(1) field set are **not** ingested or embedded. A downstream NSS integrator (who holds CNSS/CNSSI-1015 access) supplies those fields via the record's **`au3_1` extension area**, configured in `maknae.yaml` — Maknae provides the *mechanism*, never the CUI *content*.

## Security criteria / acceptance tests

- Every connection decision (accept/deny) and every request (verb/outcome) emits a record carrying all AU-3 elements + the AU-3(1) fields above; a fail-closed rejection is audited (ADR-0005 negative suite).
- Timestamps are UTC (or carry an explicit offset), sub-second.
- The JSONL sink and the journald/syslog mirror both receive the record; a `maknae.yaml`-configured SIEM endpoint receives it when set.
- Inability to open the primary audit sink at startup → the daemon fails closed; a runtime write failure to the primary sink → the offending request is not served (fail closed).
- The reserved `integrity` envelope round-trips (present, empty) and the record canonicalizes deterministically (so ADR-0007 signing is a clean add).
- No CUI-derived field list or event catalog appears in the source tree; `au3_1` is populated only from config.

## Scope boundary

This ADR covers audit **content, sinks, and compliance posture** for Stage 3a. It does **not** cover: the **cryptographic** audit integrity/non-repudiation mechanism (AU-9(3)/AU-10 → **ADR-0007**); audit **review/reduction/reporting** (AU-6/AU-7 — later); **retention** policy (AU-11 — deployment); or the CNSSI-1015 NSS specifics (deployer-supplied via `au3_1`).

## Consequences

- **Positive:** a public-standards-compliant audit *content* schema from day one, crypto-ready and SIEM-ready; the OSS/CUI boundary keeps the project clean of controlled content; the group-based-authz ↔ AU-3(1) alignment is a natural fit.
- **Negative / accepted:** the deployment is not AU-9(3)/AU-10-complete, and — per Decision 2 — its closure is **not yet a committed obligation** (it needs a not-yet-existing amendment upgrading ADR-0007's optional signed anchor to a MUST-for-NSS). A **known, tracked** compliance gap that blocks a real ATO until closed. Journald/macOS-unified-log mirroring is best-effort operational persistence, not the tamper-evident trail (that is AU-9(3), pending that ADR-0007 amendment).

## Amendment (2026-09-07, #158) — primary failure persists

**Corrected:** the sink previously recovered a poisoned writer mutex and allowed later appends after a write or synchronization failure. A partial JSONL record could therefore absorb the next record while that append returned success. That acknowledgment is unsuitable for audit-before-mutate. A primary write, synchronization failure, or writer panic now refuses every subsequent append for the lifetime of that sink; the failure state is protected by the same mutex as the file. The system-log mirror remains best-effort and cannot restore primary availability. The primary now opens through `maknae-io`: an existing nonempty file without a final newline refuses startup, without repairing or truncating it. A new audit file is created exclusively, validated, synchronized, and its same pinned parent directory synchronized before admission succeeds. The established file and its parent are synchronized on reopening too. This establishes the audit name before an intent may authorize an effect; it is not a repair or cryptographic integrity mechanism.

## Amendment (2026-08-28, #77 — the read verb, the object element, the disclosure invariant, the action vocabulary)

Dated as-built amendment; one statement, four coupled deltas (rides the #77 PR):

1. **The record gains an optional `object` element** (AU-3 "objects involved"): the canonical decided resource path for resource-bearing verbs (`fs.read`); absent for resource-free verbs — additive for them. Without it, two denied paths under one deny pattern were indistinguishable in the trail. **Amended 2026-08-30 by [ADR-0009](ADR-0009-subject-side-os-dac-evaluation.md) decision 6:** for `fs.read` the *decided* resource path is now the **kernel-reported path of the subject's delegated fd**, not the client-supplied string — so the deny list evaluates ground truth (`~/innocent → ~/.ssh/id_rsa` is decided on `.ssh/id_rsa`). The two can legitimately differ, so **the record carries both**: `object` holds the decided (kernel-reported) path, and the client-supplied string is recorded separately as *what was asked*. A trail carrying only one is unreconstructable. **Implemented 2026-08-30 as a new optional field `object_requested`, emitted ONLY when it differs from `object`** — so its presence, not its value, is the signal that a client named one object while a different one was evaluated. Additive and `skip_serializing_if`, so records for non-diverging reads and for every resource-free verb are byte-identical to before; the canonicalization contract is unaffected.
2. **The `action` field's value domain changes** (NOT additive): it now carries the PDP action-class name — `liveness.ping`, `admin.whoami`, `fs.read` — instead of the bare verb (`ping`/`whoami`). Scope: VERB-DECIDED request records only; the transport/boot pseudo-actions (`connect`, `read`, `decode`, `authz`, `posture`) are not PDP actions and keep their names. Decision and record share one vocabulary; the AU-3(1) reason/action pairing follows it.
3. **The ordering invariant generalizes: no DISCLOSURE without a durable record.** The verb enumeration above ("read-only (`whoami`/`ping`)") is superseded: `Read` joins Stage 3a's read-only set, and its dispatch (an anchored open + bounded read — an observable access) happens BEFORE the record, because the outcome (content/oversize/refusal) is only knowable after the open. The frame still gates on the durable append: content read into daemon memory whose record cannot append is dropped (zeroized) undisclosed. Internal access before the record is accepted; **Corrected 2026-09-07: audit-before-MUTATE moved from closed #84 to ON #158 and now serves the three filesystem mutation verbs, as described in the mutation amendment.** **Wording corrected 2026-08-30 ([ADR-0009](ADR-0009-subject-side-os-dac-evaluation.md)):** "an anchored open" is stale — the daemon performs no anchored open on the read path; the **subject's own process** opens the object and delegates the descriptor. **The invariant is unchanged and slightly strengthened**: the daemon's first observable access is a read of a descriptor the subject already held, and the frame still gates on the durable append. The client-side open is not a Maknae disclosure — a subject reading its own file under its own authority discloses nothing Maknae mediated.
4. **Deny reasons are audit-only** (restating #85's spec §4.4 as record contract): the PDP's reason (including matched deny-pattern source text) appears in `outcome.reason` and never on the wire; the wire carries fixed generic strings.

## Amendment (2026-08-29, #67) — the action vocabulary drops the `acp.` prefix

**The `action` field's value domain changes again (NOT additive).** `acp.fs.read` → `fs.read`, and the class vocabulary becomes `liveness` / `admin` / `session` / `fs` / `terminal` / `mcp` / `kernel`.

**Rationale.** The `acp.` prefix bound capability domains to a protocol version. ACP v2 removes the Client filesystem and terminal surfaces entirely and delegates them to client-provided MCP servers (`design/references/2026-08-28-acp-protocol-assessment.md`, pinned at upstream `9f40e01`), so a class name carrying that prefix asserts a mapping that upstream no longer has. `session` keeps its name because it exists in both ACP versions; `fs` and `terminal` are capability domains that outlive whichever protocol carries them.

**Trail continuity.** Records written before this amendment carry `acp.fs.read`. An auditor querying filesystem reads across the boundary must union the old and new names. No migration of existing records is performed — the trail is append-only by design, and rewriting it would be a worse defect than the discontinuity.

**The `outcome` value domain is PINNED by this amendment.** It was never enumerated, and the record types the fields as free-form strings, so R8 had nothing to govern until now: `result` ∈ {`permit`, `deny`}; `posture` ∈ {`authorized`, `unauthorized`, `unavailable`, `refused-oversize`, `refused-outside-root`, **`not-implemented`**}. The new value carries #67 D7's requirement that a record distinguish **decided-and-not-performed** from decided-and-done — an enumerated term that is permitted and then answered `NotImplemented` records `result: permit` with `posture: not-implemented`, so a Permit-then-NOOP can never read as a completed action.

**Scope.** Verb-decided request records only, as with the previous amendment. The boot posture record carries `hrot_sealed` / `plaintext_degraded` / `unverified` and is deliberately OUTSIDE this domain. The transport/boot pseudo-actions (`connect`, `read`, `decode`, `authz`, `posture`) are not PDP actions and keep their names. **No verb's action string may equal a pseudo-action** — nothing structural enforces this now that the `acp.` prefix is gone, so it is a test obligation.

## Amendment (2026-09-05, #189) — the journald mirror is real; `audit.siem` is retained but refuses boot

Dated as-built amendment; rides the #189 PR. Six statements:

1. **Decision 3's mirror is implemented, and its scope narrows to Linux.** The stub is replaced by a best-effort, non-blocking `UnixDatagram` write of the systemd **native journal protocol** — written directly, with **no `libsystemd` FFI**, so ADR-0002's 100% Rust TCB is intact. (journald has **no file-input plugin** — its inputs are the native socket, `/dev/log`, unit stdout, `kmsg` and the audit netlink — so the mirror cannot be replaced by pointing journald at the JSONL.) Records carry the canonical JSON verbatim in `MAKNAE_RECORD`, plus `SYSLOG_IDENTIFIER=maknaed` and filterable `MAKNAE_ACTION` / `MAKNAE_OUTCOME` / `MAKNAE_SUBJECT`. journald is present on all supported targets (RHEL 9, RHEL 10, Debian 13), and the round-trip is verified byte-identical against the JSONL line on all three. **macOS is a named no-op** — `/run/systemd/journal/socket` does not exist there, so `connect()` fails and the mirror is structurally `None`; the darwin unified-log appender is **#222**. *(Amended 2026-09-06 by #222: "no `cfg` gate anywhere in the crate" is no longer true. No **module** is gated — every file compiles on both platforms — but `sink.rs` now carries `cfg`s at the **import boundary** (the `Mirror` alias pair and a macOS `DEFAULT_JOURNAL_SOCKET`) and throughout its test module. What remains true, and is the load-bearing part, is that the darwin **absence** of journald is structural rather than conditionally compiled.)* **Since macOS on Apple Silicon is a production target, not a dev convenience** (operator ruling 2026-08-30; `packaging/isolation-contract.md`), that is a **supported-platform gap on a shipping platform**, not a reduced-profile footnote — and ADR-0002's 100% Rust TCB applies to any darwin appender with full force, so there is no dev-box exemption available for an FFI shim. *(Clarified 2026-09-05: #222 as first filed asserted the opposite and cited two documents that do not mention macOS.)*

2. **Decision 3's SIEM seam is NOT implemented, and `audit.siem` now refuses boot.** The key is **retained** (operator ruling 2026-09-05) for the export seam tracked as **#223**, so it stays parsed, disclosure-screened and gate-anchored. But a *configured* `audit.siem` makes `maknaed` exit **4** — its own code, distinct from the authz refusal's 3 — and the refusal is itself audited, following the ordering rule `run.rs` already states for the authz gate. This applies the discipline of `posture: not-implemented` (the 2026-08-29 amendment) one layer up, at boot.

3. **Decision 3's third acceptance clause is SUPERSEDED.** It read *"a `maknae.yaml`-configured SIEM endpoint receives it when set."* Nothing receives it when set; setting it refuses boot. Replaced by: *off-host offload is a host log agent tailing the JSONL, configured outside Maknae.*

4. **The AU-9(2) control-mapping row is AMENDED in place.** Its Property read *"…SIEM offload to a separate system **when configured**"* — a state the daemon now refuses to enter, so as written it asserted an unreachable control. AU-9/AU-9(2) remain satisfied: the control requires storage on a physically separate system, not that Maknae be the transport. **The control rests on the durable JSONL sink, read by a deployer-run agent under an explicit POSIX ACL** (`packaging/README.md`); it does **not** rest on the journald mirror, which is best-effort and drops under backpressure.

   The grant is four commands, not one, and that was established by executing it rather than assuming it: `/var/log/maknae` is `0700 _maknae:_maknae` so **no group membership grants anything**, and `audit.jsonl` carries `chattr +a`, on which the kernel refuses every write-xattr operation (`setfacl` → `EPERM`; `CAP_LINUX_IMMUTABLE` does not bypass it). Two operational hazards are documented with it: a package upgrade re-`chmod`s the directory and **zeroes the ACL mask while leaving the entry visible in `getfacl`**, and a confined SELinux agent additionally needs `logging_read_generic_logs()`.

   **A receive-only forwarder plane was designed and rejected**: it would re-implement mature tooling and add a third plane identity, and `packaging/common/maknae.te` already restricts `maknaed_t` to one operator-labeled port, so it bought no property SELinux did not already enforce. **Accepted posture:** at MVP Maknae ships no off-host egress mechanism of its own; per operator ruling 2026-09-05 this is not a concern before assessment, and the capability is expected back via #223.

5. **Refusal-path semantics — the mirror is the sole record for a non-durable append.** The mirror is called on **every exit from `append` after the record canonicalizes**, including the two circuit-breaker refusals *and* a `spawn_blocking` join failure, where the primary never durably wrote. That is deliberate: when the primary is wedged, the mirror is the last-chance record. Consequently records exist in journald that are **absent from the JSONL**, so every mirrored record carries **`MAKNAE_PRIMARY`** ∈ {`ok`, `refused-breaker-open`, `refused-at-capacity`, `write-failed`}. Without it the two sinks diverge silently and an auditor cannot distinguish "missing from the JSONL" from "never generated". The mirror takes no breaker admission — the breaker bounds *blocking* backends and a non-blocking datagram send cannot wedge; routing it through would let a wedged primary suppress the last-chance mirror. **On macOS, until #222, a refused or failed append was recorded nowhere** — an asymmetry stated here rather than discovered later. *(Closed 2026-09-06 by #222: all four `MAKNAE_PRIMARY` values are delivered to the unified log and asserted exactly, against the real logger.)*

6. **MAC policy ships with the feature.** `logging_send_syslog_msg(maknaed_t)` is added to `maknae.te`. The gap was established against the **compiled** policy (`sesearch -A -s maknaed_t -t maknaed_t -c unix_dgram_socket` → empty), which also corrected a wrong assumption: on el9 **and** el10 the journal socket is labeled **`syslogd_var_run_t`**, not `devlog_t`, so a hand-rolled `devlog_t` rule would have missed the real label. The refpolicy attribute covers both. Verified under enforcement on all three targets with the appender's own record as a positive guard — zero denials on Rocky 9, Rocky 10 (STIG'd, fapolicyd active) and Debian 13. **AppArmor needs no profile change**, demonstrated rather than assumed: `abstractions/base` carries `@{run}/systemd/journal/socket w,`, and a complain-mode shakeout followed by an enforce run were both clean.

## Amendment (2026-09-06, #222) — the macOS unified-log appender is real; ADR-0002 is NOT amended

Dated as-built amendment; rides the #222 PR. It closes the darwin gap the #189 amendment named as *"a supported-platform gap on a shipping platform."* Seven statements:

1. **The darwin appender exists, and it needs no ADR-0002 amendment.** Records reach the macOS unified log through **`syslog(3)`**, called via `nix`'s safe wrapper — `nix` was already a dependency of this crate, and enabling its `syslog` feature resolved **no new package** (`git diff --exit-code Cargo.lock` empty). libSystem is already bound by every Rust binary on the platform, so this is not a new C dependency and there is **no C shim** — which `os_log` would have required (`build.rs` + `wrapper.c`), and which ADR-0002's 100% Rust TCB does not permit on a production target.

2. **`syslog(3)` is the correct API here, and that was established from the SDK rather than from folklore.** In the macOS 26.5 SDK, `syslog(3)`'s declaration carries **zero** deprecation markers, while `asl.h` carries **46**; Apple's own `logger(1)` links `_syslog$DARWIN_EXTSN`. The API is bridged into the unified log by the platform, so records are ordinary unified-log entries. **Ruled out and recorded so they are not re-proposed:** `os_log` (compiles C); writing to `/var/run/syslog` directly (measured: it *accepts* datagrams and *discards* them — the worst possible failure mode, silent success).

3. **Every record emits at `LOG_WARNING`, unconditionally — never at info.** Measured: `LOG_WARNING` maps to the unified log's **Default** message type, visible in a plain `log show` and persisted to disk; `LOG_INFO` maps to the **info** type, hidden without `--info` and memory-backed, so a `permit` record might never reach disk at all. Severity is therefore **not** where the macOS mirror carries deny/permit — `MAKNAE_OUTCOME` inside the line is. This is the one deliberate divergence from the journald path, which does derive `PRIORITY` from the outcome.

4. **Oversize records are DROPPED, never truncated.** macOS clips a submitted message at **1015 bytes** and **marks** the result with a trailing `<…>`. A clipped record is corrupt JSON regardless of the marker, so an oversize line is dropped instead: a dropped record is visibly absent, a truncated one is corrupt while looking present. The cap is **bisected, and verified against the platform in both directions** — a line of exactly 1015 bytes round-trips unmarked at 1015; one byte more comes back as 1020 bytes ending in the marker. *(The constant was wrong twice before this, both times by reading a length off an already-truncated record: 1024, then 1018 — which is the char count of the wreckage, 1020 being its byte count. Neither is the cap.)*

5. **On macOS the audit line must be PARSED, never grepped whole — an asymmetry with journald that is load-bearing.** `syslog(3)` delivers ONE undelimited line, so the structured fields and the verbatim `MAKNAE_RECORD` payload share a single string. `object` is controlled by the subject the record is about (ADR-0009: the kernel-reported path of the subject's own delegated descriptor), so interpolating it into that line would let a subject **forge `MAKNAE_OUTCOME=permit` into their own deny record**. It is therefore omitted from the macOS summary entirely — it is already carried verbatim inside `MAKNAE_RECORD`, so nothing is lost — and every value still interpolated passes a reject-not-escape scrub enforced by a newtype whose constructor is private.

   **Be precise about what that buys:** the payload is canonical JSON carried verbatim, so a hostile `object` still places the literal bytes `MAKNAE_OUTCOME=permit` *inside* `MAKNAE_RECORD` on a deny record. What is guaranteed is an **uncontaminated structured prefix and a trustworthy extraction anchor**. So: read the prefix, then everything after the **first** `MAKNAE_RECORD=` — `find`, never `rfind`, since under hostile input the last occurrence is inside the payload. `journalctl MAKNAE_OUTCOME=permit` is a true field match on Linux; the macOS equivalent is **not** `grep MAKNAE_OUTCOME=permit`.

6. **The macOS log store is a STRONGER tamper-resistance boundary than journald's.** `/var/db/diagnostics` is `drwxr-x--- root:admin`, so `_maknae` can **write** to the unified log and can never **read or modify** what is already there. An agent cannot rewrite the trail it emitted. The consequence for shipping is the flip side of the same property: the unified log is **not** the macOS offload path, because a log tailer would need `admin` — a grant not to recommend. On macOS the JSONL under the AU-9(2) POSIX-ACL procedure is the offload path, and the unified-log mirror is a tamper-resistant second copy.

7. **Two properties are ASSUMED rather than verified, and are stated here rather than left to look proven.** First, **non-blocking**: the Linux mirror buys it with `O_NONBLOCK` and proves it with a full-buffer regression test; `syslog(3)` exposes no such flag and `logd` is not saturable from userspace, so the darwin test is a gross-stall detector only. If `logd` ever applies real backpressure, the call is synchronous on a tokio worker. Second, the **launchd daemon context does not exist yet** — packaging (`_maknae` user, plist, `.pkg`, Apple signing chain) is tracked as **#227**, so the behaviour under a real daemon context is inferred from a user-context run.

   A third, accepted: **on macOS, `cargo test` emits production-shaped audit records into the unified log and they are not separable from real ones.** Two marker designs were built and rejected — a `cfg(test)` marker cannot reach integration tests, which link the library built without `--cfg test`; and an env-var marker is worse, being a **runtime-settable label on production audit records** that anyone controlling the daemon's environment could stamp on genuine ones. That is a known property of running the suite on a host, not a defect papered over.


## Amendment (2026-09-07, #158) — durable intent and attributed mutation outcomes

The reference monitor verifies immutable execution evidence and obtains a real composed Permit for every intended resource before appending an intent. The intent carries the prepared operation, authorized paths, and content length where applicable; file bytes are never audit data. An intent append failure prevents daemon execution and prevents issuance of a namespace attempt grant.

Existing-file replacement executes through the subject's nontruncating writable descriptor. Its completion is `KernelObserved`, with `Applied`, `NoEffect`, `Partial`, or `DurabilityUnknown` recording what the I/O operation established. Successful completion must append durably before a success response. The operation and completion owner survive a disconnected waiter, retaining bounded worker capacity until the actual work finishes. A completion append failure cannot undo already changed bytes and never produces a success response.

Create-on-absent, delete, and mkdir execute in the CLI under the subject's credentials after a durable intent authorizes an attempt (ADR-0009). Progress and completion are `ClientReported`, including every reported affected path and a correlated index. Validation checks scope, ordering, uniqueness, effect kind, and limits; it does not verify the report's truth. Every acknowledgment follows its durable append. The supported CLI waits for acknowledgment before another batch, uses at most one effect per batch, and stops on transport failure without retrying uncertain work. A lost report or deadline yields an incomplete attempt, not a claim of no effect or rollback. A client-reported success remains a client claim even when its record is durable.

Limits are 4096 effects, depth 128, 4096 UTF-8 bytes per path, at most 32 effects accepted per report, the configured frame cap, and one absolute attempt window from `transport.read_timeout_ms`. Checks precede the next syscall; a blocked syscall may outlive the window. Namespace success means the OS accepted that syscall, not that directory metadata is crash durable. File-content writes synchronize their file descriptor; the separate audit-name synchronization requirement above remains mandatory.
